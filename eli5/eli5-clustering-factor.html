같은 책장을 몇 번씩 다시 열어요

안내판 순서대로 걸을 때마다
매번 다른 책장으로 뛰어다녀요 😵

🔢 점수 매기는 법

🚶 안내판(리프)을 순서대로 걸으며
"책장을 몇 번 갈아탔나?" 세기
😇최고 점수
= 책장(블록) 수
갈아타기 최소
😈최악 점수
= 책(행) 수
한 권마다 갈아탐

이 숫자가 클러스터링 팩터(CF).
낮을수록 착한 책장!

DB는 블록 단위로 읽으니까, 진짜 비용은 "몇 권"이 아니라 "책장을 몇 번 여나"예요

🧭 옵티마이저가 이 점수를 봐요

😇 점수 좋음
➡️ "인덱스로 가자!"
넓은 범위도 인덱스 OK
😈 점수 나쁨
➡️ "차라리 첫 장부터
다 읽자(풀 스캔)"

같은 인덱스라도 CF가 나쁘면
옵티마이저가 인덱스를 버려요.
"인덱스 있는데 왜 안 타지?"의 단골 범인 ⭐

🤔 어떤 컬럼이 착할까?

📅 쌓이는 순서 컬럼
주문번호, 입사일, 등록일
들어온 순서 = 저장 순서
🎲 제멋대로 컬럼
전화번호, 이메일, UUID
저장 순서와 무관

테이블은 보통 들어온 순서로 쌓이니까,
그 순서와 닮은 컬럼의 인덱스가 착해요

CF는 인덱스마다 달라요 — 같은 테이블이라도 어떤 인덱스는 착하고 어떤 인덱스는 엉망

📝 정리하면

CF = 인덱스 순서대로 걸을 때
책장(블록)을 갈아타는 횟수 — 낮을수록 좋음
최선 = 블록 수 · 최악 = 행 수
CF가 나쁘면 옵티마이저는 넓은 범위에서
인덱스 대신 풀 스캔을 고른다
