🖊️ 지워지지 않는 장부 만들기

※ 실제 사례를 바탕으로 주문번호·금액·회사명 등 식별 정보를 바꾼 가상 사례입니다.

지난번 환불 사고, 궁극적으로 어떻게 고쳐야 할까요? — 아웃박스 패턴 5분 설명

복습 · 지난 사고

문제는 "연필로 적다가 통째로 지운 것"이었어요

🤖 예전 시스템: 은행 송금 3건 중 2번째가 실패하면 → 1번째 기록까지 싹 지움 🧽
🏦은행(PG사)
돈은 이미 나감
송금은 지우개로 못 지움
📒장부(DB)
기록은 사라짐
연필+지우개(롤백)라서

DB 트랜잭션 = 연필로 적다가 실패하면 통째로 지우는 규칙.
회사 안에서만 쓰면 완벽하지만, 은행 송금은 지워지지 않아서 둘이 어긋나요.

핵심 아이디어

"하기 전에 적고, 할 때마다 볼펜으로 적는다"

📝 → 💸 → 🖊️ → 🤖

① 할 일 먼저 적기 → ② 돈 보내기 → ③ 한 건마다 즉시 기록 → ④ 순찰 로봇

한 문장 요약: 돈 보내는 일과 장부 적는 일을 한 묶음(트랜잭션)에 넣지 않는다.
대신 "적기 → 실행 → 적기"로 쪼개고, 한번 적은 건 절대 안 지워요(볼펜 🖊️).

1단계 · 의도 기록 (Outbox)

돈 보내기 전에, "보낼 예정" 목록부터 적고 도장 꽝

🧑‍💼 고객: "티켓 2 환불해주세요"
⬇️ 돈은 아직 1원도 안 움직임
📮 아웃박스 (보낼 편지함)
□ 큰 지갑에서 $150 환불하기 — 접수번호 #A1
□ 업그레이드 지갑에서 $30 환불하기 — 접수번호 #A2
상태: 진행중 커밋 도장 ✓

이 단계에서 실패하면? 그냥 없던 일. 돈이 안 움직였으니 아무 피해 없어요.
도장(커밋)을 찍었으니 이 목록은 이제 안 지워져요.

2단계 · 실행 (Idempotency Key)

접수번호를 들고 은행에 가요 — 같은 번호는 한 번만!

💁 은행 창구: "접수번호 #A1? 처음 보는 번호네요. 송금해드릴게요 ✅"
💁 은행 창구: "또 #A1? 그건 아까 처리했어요. 두 번 안 보내요 🙅"

접수번호 = idempotency key. 지난 사고 때 고객이 십수 번 다시 눌러 매번 돈이 또 나갔죠?
이제는 몇 번을 다시 시도해도 같은 번호면 은행이 한 번만 실행해요. 재시도가 안전해져요.

3단계 · 건별 볼펜 기록

한 건 끝날 때마다 볼펜으로 바로 적어요

📮 아웃박스
☑ #A1 $150 — 완료 🖊️ 즉시 커밋
□ #A2 $30 — ❌ 실패! (은행 오류)
상태: 부분완료

여기가 지난 사고와의 결정적 차이. #A2가 실패해도 #A1 기록은 이미 볼펜으로 적혀서 안 지워져요.
예전엔 큰 트랜잭션 하나에 묶여서 #A2 실패가 #A1 기록까지 지웠어요(연필 🧽).
이제 은행과 장부가 절대 어긋나지 않아요.

4단계 · 순찰 로봇 (대사 스케줄러)

못 끝낸 일은 로봇이 주기적으로 마무리해요

🤖 🔍 📮

로봇이 아웃박스를 순찰: "진행중·부분완료가 남아있네?"

  • ❌ 실패한 건(#A2) → 같은 접수번호로 다시 시도 (두 번 나갈 걱정 없음)
  • ❓ 응답을 못 받은 건(타임아웃) → 은행에 "#A3 처리됐어요?" 물어보고 장부를 진실에 맞춤
  • ✅ 다 끝나면 상태를 완료로 바꾸고 순찰 끝

"보냈는지 안 보냈는지 모르는" 애매한 실패도 미아가 되지 않아요.
접수번호가 남아있으니 언제든 은행에 확인해서 맞출 수 있거든요.

보너스 · 하이브리드

고객은 빠르게, 실패는 로봇이 — 두 길을 같이 써요

🏃빠른 길 (동기)
커밋 직후 바로 실행
고객은 몇 초 만에 결과 확인
🤖안전망 (비동기)
실패 건만 로봇이 재처리
고객은 기다릴 필요 없음

평소엔 지금처럼 즉시 환불되는 경험 그대로,
문제가 생긴 건만 로봇이 뒤에서 조용히 마무리해요. 둘 중 하나가 아니라 둘 다예요.

  • 📝 1단계: 보낼 목록(아웃박스)부터 적고 커밋 — 실패해도 피해 0
  • 🎫 2단계: 접수번호(idempotency key)로 실행 — 재시도해도 한 번만
  • 🖊️ 3단계: 한 건 끝날 때마다 즉시 커밋 — 뒤가 실패해도 앞 기록 보존
  • 🤖 4단계: 순찰 로봇이 남은 건 재시도·확인 — 애매한 실패도 회수
