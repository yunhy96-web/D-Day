# PackFit 설계 스킬

물류창고에서 **여러 물건을 하나의 상자에 담는 방법**을 시뮬레이션하는 사이드 프로젝트.
상자 규격(W×D×H)과 물건들의 규격을 입력하면 → 3D bin packing 알고리즘으로 배치 계산 → Three.js로 시뮬레이션 렌더링.

설계 원칙: **작게, 프론트만, 서버 없음.** 알고리즘은 브라우저에서 돈다. 필요해질 때까지 백엔드/DB/로그인 없음.

## 1. 기술 스택 (확정)

| 영역 | 선택 | 이유 |
|------|------|------|
| 빌드 | Vite + TypeScript | 가장 가벼운 SPA. 프레임워크 없음 |
| 3D | Three.js (+ OrbitControls) | 상자·물건을 `BoxGeometry` 로 그리면 끝 |
| UI | 순수 HTML form + 약간의 DOM 코드 | 입력 폼 하나·결과 패널 하나. React 불필요 |
| 상태 저장 | `localStorage` | 마지막 입력값 복원용. 그 이상 없음 |
| 배포 | 정적 호스팅(Vercel/GitHub Pages) | `dist/` 업로드 |

구조:
```
PackFit/
  index.html          # 입력 폼 + 3D 캔버스 + 결과 패널
  src/
    main.ts           # DOM 바인딩, 실행 버튼 → pack() → render()
    pack.ts           # 순수 함수. 알고리즘. DOM 의존 X (테스트 대상)
    render.ts         # Three.js 씬 구성
    types.ts
  test/pack.test.ts   # vitest. 알고리즘만 검증
  docs/design/        # 설계 산출물(이 스킬의 결과)
```

## 2. 도메인 모델

단위는 **mm**, 무게는 **g** (정수). 방향(rotation)은 6가지 축 순열.

```ts
type Dim = { w: number; d: number; h: number };        // 가로·세로·높이

type Box = Dim & {
  wall: number;        // 상자 내벽 여유 (포장재/벽 두께). 기본 10mm. 6면 전부 적용
  maxWeight?: number;  // 선택. 초과 시 실패
};

type Item = Dim & {
  id: string;
  name: string;
  qty: number;         // 같은 물건 n개 → 내부에서 n개로 펼침
  weight?: number;
  gap: number;         // 물건 사이 최소 간격(완충재). 기본 5mm. 각 면에 적용
  noRotate?: boolean;  // "이 방향 유지" (액체·유리 등). 높이 축 고정
  fragile?: boolean;   // 위에 아무것도 못 올림 (Phase 2)
};

type Placed = {
  item: Item;                 // 원본 참조
  pos: { x: number; y: number; z: number };   // 상자 내부 좌표 (원점 = 내벽 좌측-앞-바닥 모서리)
  dim: Dim;                   // 회전이 적용된 실제 치수 (gap 미포함)
  rotation: 0 | 1 | 2 | 3 | 4 | 5;
};

type PackResult = {
  placed: Placed[];
  unplaced: Item[];           // 못 담은 것
  fillRate: number;           // 부피 채움률 0~1 (물건 순수 부피 / 상자 내부 유효 부피)
  totalWeight: number;
};
```

### 간격 처리 규칙 (핵심)
- **상자 유효 공간** = 내부 치수 − `wall × 2` (각 축). 이 안에만 배치.
- **물건 점유 공간** = 실제 치수 + `gap × 2` (각 축). 알고리즘은 이 "부풀린 박스"로 충돌 판정.
- 렌더링은 실제 치수로 그리고, 부풀린 영역은 반투명으로 표시(옵션).
- 이렇게 하면 알고리즘은 간격을 전혀 몰라도 됨 → 알고리즘 코드가 단순해짐.

## 3. 적재 알고리즘

### Phase 1: Extreme-Point + Best-Fit-Decreasing (EP-BFD)
3D bin packing의 표준 휴리스틱. 구현 ~150줄. 이거면 실무 90% 케이스 충분.

```
1. items를 qty로 펼치고, 부피 내림차순 정렬 (큰 것부터)
2. extremePoints = [(0,0,0)]
3. 각 item에 대해:
     후보 = 모든 EP × 허용 회전(6 or 2)
     유효 후보 = 상자 안에 들어감 && 기존 배치와 겹치지 않음 && 바닥 지지됨
     best = 유효 후보 중 점수 최소 (점수 = 낮은 z 우선 → 낮은 y → 낮은 x)
     배치하면 새 EP 3개 추가 (배치된 박스의 +x, +y, +z 모서리), 
     기존 EP 중 배치된 박스 내부에 들어간 것 제거
   못 놓으면 unplaced에 추가
```

- **지지 판정(stability)**: 물건 바닥면의 ≥ 70% 가 상자 바닥 또는 다른 물건 윗면 위에 있어야 함. 공중부양 방지.
- 충돌 판정은 AABB O(n) 스캔. 물건 수 ≤ 100 가정. `// ponytail: O(n²), 그리드 인덱스는 n>500일 때`
- 결정적(deterministic)이어야 함 → 같은 입력 = 같은 결과. 테스트 가능.

### Phase 2: 개선(필요해지면)
- 여러 정렬 순서(부피/높이/바닥면적 내림차순)로 N번 돌려 fillRate 최고 선택 → 코드 10줄 추가로 품질 큰 향상
- `fragile` 위에 적재 금지, `maxWeight` 검사
- 여러 상자 후보 중 **가장 작은 상자 추천** (표준 박스 목록 미리 등록)

### Phase 3: "AI" (선택, 검증 후)
- 정렬 순서에 대한 **유전 알고리즘/시뮬레이티드 어닐링** — EP 휴리스틱 위에 순서만 최적화. 브라우저에서 1~2초 내
- LLM은 여기서 배치를 계산시키지 않는다(공간 추론 약함, 비결정적). 쓴다면 "왜 이렇게 담았는지 설명" 또는 "취급 주의 물품 자동 태깅" 정도.

## 5. 검증 (테스트)

`test/pack.test.ts` — 알고리즘만. UI 테스트 없음.
1. 상자 100×100×100, 물건 50×50×50 × 8개 → 8개 전부 배치, fillRate 1.0 (gap=0, wall=0)
2. gap=5 적용 시 같은 케이스 → 8개 못 들어감 (60×60×60 이 필요) → unplaced 확인
3. wall=10 → 유효공간 80³ → 50³ 은 1개만
4. 상자보다 큰 물건 → unplaced
5. 회전 필요한 케이스: 상자 100×50×50, 물건 50×100×50 → 회전해서 배치됨; `noRotate` 면 실패
6. 배치 결과 간 AABB 겹침 없음 (모든 테스트 공통 assert)
7. 모든 배치가 상자 유효 공간 안에 있음 (공통 assert)

## 7. 하지 않는 것 (YAGNI)
- 백엔드, DB, 로그인, 다중 사용자
- 여러 상자에 나눠 담기(multi-bin) — 단일 상자만. 필요해지면 "안 들어간 것으로 다음 상자" 반복이면 됨
- 비직육면체 물건(원통·불규칙) — 외접 직육면체로 입력
- 무게중심 계산, 적재 하중 한계
- 실시간 물리 시뮬레이션 (Cannon.js 등) — 배치는 계산으로, 렌더는 정적
